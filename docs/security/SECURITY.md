# Security Policy

`wiki-agent` 是 local-first 的 Agentic RAG 项目。
本页说明仓库的安全边界、已实现控制、已知限制和漏洞报告建议。

## 本地数据与秘密

秘密和本地数据默认不应进入 Git。

仓库约定：

- `.env`：本地 API 地址、密钥和运行配置，不跟踪；
- `.env.example`：只包含安全占位符，可以跟踪；
- `notes/`：本地知识源，不跟踪；
- `models/`：本地模型缓存，不跟踪；
- `var/`：索引、Trace、评测原始产物和其他运行文件，不跟踪。

这些目录被忽略不代表其内容已加密或已脱敏。
请使用操作系统权限、磁盘加密和适当的备份策略保护本地文件。

不要在源码、配置、测试 fixture、文档、issue、日志或 Trace 中提交真实密钥。
如果秘密曾被提交，请立即在服务端轮换或吊销；仅删除当前文件不足以撤销已经泄露的凭据。

## 已实现的安全控制

当前运行时提供以下纵深控制：

- 工具按名称注册并使用结构化参数 schema；
- 工具参数在执行前解析和校验；
- 默认只向模型暴露核心工具，其他工具组按需加载；
- `PermissionPolicy` 对调用做 `allow | ask | deny` 决策；
- 高风险操作可以要求用户审批；
- 文件工具限制路径和写入 scope；
- shell 等能力具有超时、输出限制或受限配置；
- 只读工具与副作用工具分开调度；
- 相同失败调用达到上限后停止重复尝试；
- Agent loop 和 RAG 调用都有预算；
- EvidenceLedger 记录检索证据，零证据断言可被强制降级为拒答；
- Trace artifact 对常见敏感字段做脱敏。

这些控制用于降低误操作和无依据回答的概率，不构成完整安全边界。

## 明确限制

- 模型输出不可信；模型可能选择错误工具、生成错误参数或误解工具结果。
- Tool Exposure 只减少模型可见能力，不是操作系统级沙箱。
- 路径校验、写入 scope 和审批不能替代最小权限的进程账户与文件权限。
- MCP 服务和外部命令拥有其宿主进程授予的权限，应单独审查和限制。
- Skill、知识文档、用户输入和工具输出都可能包含恶意指令。
- 本项目不能宣称彻底解决 prompt injection。
- 证据策略不能证明每个答案断言都受来源支持，也不能保证来源真实。
- 脱敏是尽力而为；原始 Trace、错误信息或工具输出仍可能包含敏感内容。
- 本地索引和 embedding 可能保留源数据特征，应按源文档同等级保护。
- 依赖项、模型文件和远程模型服务具有各自的供应链与隐私风险。

对于高敏感数据或高风险写操作，请在隔离环境中运行，使用专用低权限账户，并保持人工复核。

## Prompt Injection 防护建议

把检索内容和工具输出视为数据，而不是可信指令：

- 不要因知识文档要求而扩大权限、泄露秘密或跳过审批；
- 仅加载完成任务所需的工具组；
- 对 shell、文件写入和外部服务使用最小权限；
- 将可写工作区与秘密目录分离；
- 在执行不可逆操作前检查目标、参数和 diff；
- 对不可信 MCP 服务使用独立进程或容器边界；
- 记录并复核异常工具序列。

这些措施只能降低风险，不能消除 prompt injection。

## 漏洞报告

如果问题可能导致秘密泄露、越权文件访问、任意命令执行、审批绕过或依赖供应链风险：

1. 不要在公开 issue 中粘贴秘密、个人数据或可直接利用的敏感环境信息；
2. 优先使用仓库托管平台提供的私密安全报告功能；
3. 如果私密报告不可用，先创建不含敏感细节的最小公开 issue，请维护者提供安全沟通渠道；
4. 提供受影响版本、最小复现、预期与实际行为、影响范围和缓解建议；
5. 在维护者确认修复和披露计划前，避免公开完整利用细节。

报告者应使用合成数据和占位凭据复现问题。

## 贡献者发布检查

提交或发布前：

- [ ] `git status --short --untracked-files=all` 仅包含预期文件；
- [ ] `.env`、`notes/`、`models/`、`var/` 未被跟踪；
- [ ] 文档、fixture、日志和 Trace 不含真实秘密或本地绝对路径；
- [ ] 新工具声明了正确的权限、风险等级、只读属性和参数校验；
- [ ] 写操作遵守沙箱路径与 write scope；
- [ ] 高风险工具具有拒绝和审批测试；
- [ ] 错误信息和 Trace 不暴露原始秘密；
- [ ] `npm test`、配置检查和知识目录检查通过；
- [ ] 依赖变更已审查来源、锁文件和已知漏洞；
- [ ] 真实模型或付费评测仅在明确授权后运行；
- [ ] `git diff --check` 通过。

安全控制或边界发生变化时，请同步更新本政策和相关测试。
